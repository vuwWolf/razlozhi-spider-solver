# Автоматическое прохождение «Паука (две масти)» на razlozhi.ru

Проект автоматизирует игру в пасьянс «Паук (две масти)» на
https://razlozhi.ru/patience-spider2: читает состояние игры через внутренний
API сайта, находит решение поиском по лучшим позициям (beam search) и
выполняет ходы через тот же механизм, что и сайт при воспроизведении истории.

## Установка

```bash
npm install
# Playwright нужен только для CLI и веб-интерфейса;
# десктопное приложение использует встроенный Chromium Electron.
npx playwright install chromium
```

## Использование

```bash
# автоматическое прохождение с видимым окном браузера
npm run solve

# то же в фоновом режиме
npm run solve -- --headless

# сухой прогон: напечатать решение, не выполняя ходы
npm run solve -- --dry-run --headless

# записать найденные ходы в текстовый файл (работает и без --dry-run)
npm run solve -- --dry-run --headless --log-file solution.txt

# один раз: авторизоваться в браузере проекта (откроется видимое окно)
npm run solve -- --login

# сыграть ежедневную колоду («задача дня», кнопка «Разложить»)
npm run solve -- --daily --headless

# решить конкретную колоду (104 символа)
npm run solve -- --deck "<code>" --headless

# параметры поиска (попытки, шаги beam search, лимит времени на попытку в мс)
npm run solve -- --attempts 8 --max-nodes 1500 --timeout 20000 --headless

# сколько разных колод перебрать, если текущая не решается (по умолчанию 10)
npm run solve -- --games 20 --headless
```

Если на какой-то колоде решение не находится, скрипт автоматически начинает
новую игру и пробует следующую колоду — до `--games` попыток. Для `--deck`
перебирать нечего, поэтому фиксированная колода разыгрывается один раз.
Точно так же `--daily` всегда делает одну попытку: `--games` в этом режиме
игнорируется.

В режиме `--daily` берётся колода дня из конфига страницы и запускается
настоящая кнопка «Разложить» — сайт получает `payload: {mode:'dotd'}` и
засчитывает результат как ежедневный. Другая колода вместо неё не подставляется,
и колода не переразкладывается заново: ежедневная игра разыгрывается один раз.

Ходы, сделанные программой, добавляются в историю сайта наравне с ручными.
Поэтому в карточке сыгранной игры доступна демка со всеми ходами, а не только
с начальной раздачей.

## Авторизация

Браузер использует постоянный профиль `~/.razlozhi-spider-solver-profile`,
поэтому логин сохраняется между запусками. Чтобы зайти один раз:

```bash
npm run solve -- --login
```

Откроется видимое окно Chromium на странице игры. Нажмите «Войти на сайт»,
авторизуйтесь, вернитесь в терминал и нажмите Enter (программа также сама
заметит логин). Если появится сообщение «авторизация сохранена в профиле» —
можно закрывать окно. Все последующие запуски, включая `--headless`, уже будут
идти под вашим аккаунтом: daily-рекорд и обычные результаты сохранятся на сайте.

## Веб-интерфейс (ветка `feature/ui`)

Локальный интерфейс в браузере — кроссплатформенный способ пользоваться
программой без терминала:

```bash
npm run web
```

Затем откройте http://127.0.0.1:3000. Сервер слушает только локальный адрес,
поэтому интерфейс недоступен из сети.

Возможности:

- режимы «Обычная игра», «Ежедневная колода» и «Своя колода»;
- кнопки «Запустить», «Войти на сайт», «Я вошёл» и «Стоп»;
- живой журнал ходов и прогресс выполнения;
- настройки поиска (попытки, шаги beam, лимит времени, число колод);
- флаг фонового режима (можно снять, чтобы видеть окно Chromium);
- сохранение найденных ходов в текстовый файл: включите «Записывать ходы в
  файл» и при желании укажите папку (по умолчанию — домашняя папка, а в
  десктопе — папка приложения `moves`). Путь к записанному файлу виден в
  статистике и в журнале.

Авторизация через веб-интерфейс: нажмите «Войти на сайт», войдите в открывшемся
окне Chromium и либо дождитесь автоматического определения, либо нажмите
«Я вошёл». Профиль сохраняется в `~/.razlozhi-spider-solver-profile`.

## Десктопное приложение Windows и macOS (Electron)

Приложение использует тот же интерфейс и `Runner`, что и веб-версия. Страница
игры отображается **внутри главного окна приложения** через `WebContentsView`,
поэтому отдельное окно браузера не открывается:

```bash
# разработка: окно Electron + встроенный локальный сервер
npm run electron

# Windows: сборка установщика NSIS
npm run dist

# macOS: отдельные сборки под Apple Silicon и Intel — только на Mac
npm run dist:mac:arm64
npm run dist:mac:x64
```

macOS-сборку удобно запускать через GitHub Actions (см. ниже).

Готовые файлы появятся в `dist/`. Браузеры Playwright **не упаковываются**:
десктоп управляет страницей через собственный Chromium Electron, поэтому
установщик стал намного меньше (~100–150 МБ).

Особенности:

- игра видна в блоке «Игра» главного окна; кнопка «Скрыть игру» позволяет
  убрать её из вида, не прерывая решение;
- окна авторизации OAuth открываются отдельно, но это окна входа, а не окно
  самой игры;
- профиль авторизации десктопа лежит в `%APPDATA%\Spider Solver\browser-profile`
  (на macOS — `~/Library/Application Support/Spider Solver/browser-profile`)
  и не конфликтует с CLI/веб-версией;
- закрытие окна завершает приложение;
- ссылки наружу открываются в системном браузере, а не внутри окна;
- поиск решения идёт в отдельном потоке, поэтому интерфейс не замирает,
  прогресс обновляется, а кнопка «Стоп» работает во время поиска;
- версия приложения отображается в шапке интерфейса;
- кнопка «Открыть папку с ходами» открывает каталог с сохранёнными решениями.

Если в корпоративной сети сайт не загружается из-за SSL-прокси, приложение
можно запустить с `SPIDER_IGNORE_CERT_ERRORS=1` — это отключает проверку
сертификатов только для отладки.

Файл пока не подписан, поэтому Windows может показывать предупреждение
SmartScreen при первом запуске.

### Сборка для macOS

**electron-builder не поддерживает сборку macOS на Windows или Linux**, поэтому
собрать `.dmg`/.zip локально нельзя. Есть два пути:

1. **GitHub Actions (рекомендуется).** В разделе Actions запустите workflow
   `Build macOS` вручную (`workflow_dispatch`). Матрица задач соберёт `arm64`
   и `x64` отдельно и выложит четыре артефакта:
   `Spider-Solver-macos-arm64-dmg`, `Spider-Solver-macos-arm64-zip`,
   `Spider-Solver-macos-x64-dmg`, `Spider-Solver-macos-x64-zip`.
2. **Непосредственно на Mac.** Выполните `npm run dist:mac:arm64` или
   `npm run dist:mac:x64`. Команда `npm run dist:mac` соберёт обе архитектуры
   последовательно. Скрипт проверит платформу и вызовет electron-builder.

Сборки раздельные: для arm64 и x64 создаются отдельные DMG/ZIP, потому что
electron-builder не собирает универсальные mac-пакеты одной командой. Браузеры
Playwright в них не попадают — игра работает через встроенный Chromium Electron.

Результат в `dist/`:

- `Spider-Solver-0.1.0-mac-arm64.dmg` / `.zip` — для Apple Silicon;
- `Spider-Solver-0.1.0-mac-x64.dmg` / `.zip` — для Intel.

Сборка **не подписана и не нотаризована**, поэтому macOS Gatekeeper при первом
запуске потребует «Открыть» через контекстное меню (или
`xattr -dr com.apple.quarantine "Spider Solver.app"`). Для публичного релиза
нужны сертификат Developer ID и учётные данные Apple: укажите
`CSC_LINK`/`CSC_KEY_PASSWORD` и `APPLE_ID`/`APPLE_APP_SPECIFIC_PASSWORD`/
`APPLE_TEAM_ID`, затем уберите `"identity": null` из `electron-builder.json`.
На macOS логин сохраняется в
`~/Library/Application Support/Spider Solver/browser-profile`.

## Как это работает

1. **Модель** (`src/model.js`) — чистая логика пасьянса. Колода сайта
   кодируется 104 символами (`index = (suit - 1) << 4 | nominal`, масти 3/4).
   Поддерживает раздачу, перекладывание одномастных убывающих хвостов,
   автоматическое удаление последовательностей K→A и проверку победы.
2. **Решатель** (`src/solver.js`) — beam search с эвристикой, в которой
   главный вес имеют одномастные убывающие серии (именно из них
   собираются последовательности K→A). Учитываются также закрытые
   карты и пустые колонки. В вебе и десктопе поиск выполняется в отдельном
   потоке (`src/solver-worker.js`, `src/solver-client.js`), поэтому UI остаётся
   отзывчивым и поиск можно прервать кнопкой «Стоп».
3. **Браузер** (`src/browser.js`, `src/electron-browser.js`) — перехватывает
   объект игры, читает состояние и выполняет ходы через `game.playHistoryItem`,
   дожидаясь завершения анимаций. CLI/веб используют Playwright и постоянный
   профиль; десктоп работает со встроенным `WebContentsView` в окне приложения.
4. **CLI** (`src/cli.js`) — при неудаче автоматически начинает новую игру
   и пробует следующую колоду; в режиме `--daily` запускает ежедневную колоду
   через кнопку «Разложить» и делает только одну попытку.
5. **Веб-интерфейс** (`src/server.js`, `src/runner.js`, `public/`) — локальный
   HTTP-сервер и страница с кнопками, прогрессом и живым журналом. `Runner`
   переиспользует ту же игровую логику и передаёт события в браузер по SSE.
6. **Отчёт** (`src/report.js`) — записывает найденные ходы в текстовый файл
   (`--log-file <путь>` или `--out <путь>`). Файл создаётся сразу после поиска
   решения, до выполнения ходов, поэтому план остаётся даже если игра прервётся.
7. **Десктоп** (`electron/`) — поднимает тот же сервер на свободном порту,
   показывает интерфейс в окне Electron и встраивает страницу игры через
   `WebContentsView`; отдельное окно Chromium и браузеры Playwright не нужны.

Победа достигается настоящими ходами: `debugWin` / `_doWin()` не
используются. В конце проверяется `final.winner === true` — то есть победу
признаёт сам сайт. Полный прогон с заданной колодой подтверждён:
`{ winner: true, foundations: 8, hidden: 0 }`.

## Тесты

```bash
npm test
```

Тесты проверяют декодирование колоды, начальную раздачу (сравнена с реальной
игрой), легальность ходов, нормализацию, раздачу, а также то, что решатель
находит решение, найденные ходы при повторном проигрывании действительно
приводят к победе и что текстовый отчёт корректно записывается в файл.

## Ограничения

- Решатель эвристический: на некоторых колодах решение может не находиться.
  `solveWithRestarts` перебирает несколько значений задержки раздачи
  (`dealPenalty`), а CLI дополнительно перебирает новые колоды (см. `--games`).
  На проверке случайных колод доля успеха высокая, но не 100%.
- Сайт может обновить вёрстку или внутренний API — тогда потребуется
  скорректировать `src/browser.js`.
