# Spider Solver — автоматическое прохождение «Паука (две масти)»

Решатель пасьянса [«Паук (две масти)» на razlozhi.ru](https://razlozhi.ru/patience-spider2).
Он читает состояние игры через внутренний API сайта, ищет решение поиском по
лучшим позициям и выполняет ходы через тот же механизм, что и сайт при
воспроизведении истории (`game.playHistoryItem`). Победу признаёт сам сайт:
в конце проверяется `winner === true`. `debugWin` / `_doWin()` не используются.

- Актуальная версия: **1.0.0** (тег `v1.0.0`).
- Исходники: <https://github.com/vuwWolf/razlozhi-spider-solver>.
- Готовые установщики Windows и macOS собираются из этого репозитория;
  конечному пользователю Node.js, Playwright и отдельный браузер не нужны.

Проверенные прогоны: фиксированная колода из 104 символов — 137 настоящих
ходов, ежедневная колода — 138 ходов; итог `{ winner: true, foundations: 8, hidden: 0 }`.

## Возможности

- Три режима: обычная игра, ежедневная колода (кнопка «Разложить») и своя
  колода по коду из 104 символов.
- Три способа запуска: CLI, локальный веб-интерфейс и десктопное приложение
  Electron с игрой **внутри главного окна**.
- Поиск в отдельном потоке: интерфейс не замирает, а кнопка «Стоп» прерывает
  поиск во время работы и проверяется между ходами.
- Живой журнал, прогресс, статистика и сохранение найденных ходов в текстовый
  файл из веб-интерфейса и десктопа.
- Отдельные сборки под macOS (Apple Silicon / Intel) и Windows x64 / ARM64.

## Установка для разработки

Нужны Node.js **20+** и npm. Playwright нужен только для CLI и веб-режима;
десктоп использует встроенный в Electron Chromium.

```bash
git clone https://github.com/vuwWolf/razlozhi-spider-solver.git
cd razlozhi-spider-solver
npm ci                          # или npm install
npx playwright install chromium  # только для CLI и npm run web
```

Быстрый старт:

```bash
npm run solve     # CLI с видимым окном браузера
npm run web       # интерфейс на http://127.0.0.1:3000
npm run electron  # десктоп с встроенной игрой (режим разработки)
```

## Командная строка

```bash
# автоматическое прохождение в видимом окне Chromium
npm run solve

# фоновый режим
npm run solve -- --headless

# показать найденный план, не выполняя ходы
npm run solve -- --dry-run --headless

# записать ходы в файл (можно вместе с --dry-run)
npm run solve -- --dry-run --headless --log-file solution.txt

# однократный вход на сайт; профиль сохранится между запусками
npm run solve -- --login

# ежедневная колода: запускается настоящая кнопка «Разложить»
npm run solve -- --daily --headless

# фиксированная колода (104 символа)
npm run solve -- --deck "<code>" --headless
npm run solve -- --deck 8xzm4s809p544t6kxzyi1ko514rloi6j36tz307jn5qsjxs3kqt1mhlp0krr077nz27oh2trl2nh5m3ypq8ji1moilqps29ny86h99yx --headless

# настройки поиска
npm run solve -- --attempts 8 --max-nodes 1500 --timeout 20000 --headless

# сколько разных колод перебрать (по умолчанию 10)
npm run solve -- --games 20 --headless
```

| Флаг | Значение по умолчанию | Описание |
| --- | --- | --- |
| `--headless` | выключен | Не показывать окно Chromium. При `--login` окно всё равно показывается. |
| `--login` | выключен | Дождаться входа на сайте и сохранить профиль. |
| `--daily` | выключен | Играть колоду дня через кнопку «Разложить». |
| `--deck <code>` | — | Играть заданную колоду из 104 символов. |
| `--dry-run` | выключен | Найти и напечатать решение, не делая ходов на сайте. |
| `--log-file <path>`, `--out <path>` | — | Записать найденные ходы в UTF-8 файл; каталоги создаются автоматически. |
| `--attempts <n>` | `8` | Число попыток поиска с разными настройками. |
| `--max-nodes <n>` | `1500` | Шагов beam search на попытку. |
| `--timeout <ms>` | `20000` | Лимит времени на попытку. |
| `--games <n>` | `10` | Сколько разных колод перебрать при неудаче. |

`--daily`, `--deck` и `--dry-run` всегда делают **одну** попытку: `--games` в
этих режимах игнорируется. В остальных режимах после неудачи запускается новая
игра со следующей колодой. Файл ходов записывается сразу после нахождения
решения — до выполнения ходов — поэтому план остаётся даже при прерывании.
Ходы добавляются в историю сайта, так что в карточке сыгранной игры доступна
демка со всеми ходами решателя.

## Авторизация

CLI и веб-интерфейс используют постоянный профиль
`~/.razlozhi-spider-solver-profile` (переопределяется переменной
`SPIDER_PROFILE_DIR`). Чтобы войти один раз:

```bash
npm run solve -- --login
```

Откроется видимое окно на странице игры. Войдите на сайт и нажмите Enter в
терминале — программа также определяет вход сама по появлению пользователя в
конфиге страницы. После этого все запуски, включая `--headless`, идут под
вашим аккаунтом, поэтому сохраняются обычные результаты и daily-рекорд.

В веб-интерфейсе для этого есть кнопки «Войти на сайт» и «Я вошёл». Десктоп
использует отдельный профиль в пользовательской папке приложения и не
конфликтует с CLI/вебом. OAuth-провайдер может открыть отдельное окно входа —
это не окно игры.

## Веб-интерфейс

```bash
npm run web
# http://127.0.0.1:3000
```

Сервер слушает только локальный адрес (`HOST` и `PORT` задаются переменными
окружения, по умолчанию `127.0.0.1:3000`) и не доступен из сети. Статус и логи
передаются в страницу по SSE (`/api/events`), управление идёт через
`/api/start`, `/api/stop`, `/api/login`, `/api/confirm-login`.

В интерфейсе есть:

- режимы «Обычная игра», «Ежедневная колода» и «Своя колода»;
- кнопки «Запустить», «Войти на сайт», «Я вошёл» и «Стоп»;
- настройки числа колод, попыток, шагов beam и лимита времени;
- флаг фонового режима (можно снять, чтобы видеть окно Chromium);
- прогресс, журнал и статистика: колода, решение, ходы, попытка, собранные
  масти и победа;
- флаг «Записывать ходы в файл» и поле папки. По умолчанию файлы идут в
  домашнюю папку, в десктопе — в `moves` внутри папки приложения. Имя файла:
  `spider-moves-<дата>-<номер игры>.txt`, путь виден в статистике и журнале.

## Десктопное приложение

Режим разработки:

```bash
npm run electron
```

Приложение поднимает тот же локальный сервер на свободном порту и показывает
интерфейс вместе со страницей игры. Игра встроена в главное окно через
`WebContentsView` и закреплена в блоке «Игра» — отдельное окно браузера не
открывается. Кнопка «Скрыть игру» убирает блок, не прерывая решение.

Особенности десктопа:

- поиск идёт в отдельном потоке, поэтому окно отзывчиво, а «Стоп» работает;
- прогресс обновляется во время поиска, а ходы выполняются последовательно;
- версия приложения отображается в шапке;
- кнопка «Открыть папку с ходами» открывает каталог сохранённых решений;
- профиль и логи хранятся в папке пользователя, а не в каталоге установки:
  Windows — `%APPDATA%\Spider Solver`, macOS — `~/Library/Application Support/Spider Solver`
  (в режиме разработки — `Electron`). Подкаталоги: `browser-profile` и `moves`;
- ссылки наружу открываются системным браузером, закрытие окна завершает приложение;
- включена одна копия приложения: повторный запуск разворачивает существующее окно.

В корпоративной сети с SSL-MITM-прокси игра может не загрузиться. Для отладки
можно запустить с `SPIDER_IGNORE_CERT_ERRORS=1` — это отключает проверку
сертификатов только для этого процесса.

## Сборка установщиков

Зависимости Playwright **не упаковываются**: десктоп управляет страницей через
свой Chromium. Готовые установщики весят примерно 110–120 МБ.

### Windows

На Windows (или кросс-сборкой с macOS/Linux):

```bash
npm run dist                          # NSIS, архитектура текущей машины
npx electron-builder --win --x64      # явно Windows x64
npx electron-builder --win --arm64    # явно Windows ARM64
```

Результат — `dist/Spider-Solver-1.0.0-setup-x64.exe` (NSIS с выбором папки,
ярлыками на рабочем столе и в меню «Пуск»).

### macOS

Собирать macOS-пакеты можно только на macOS: electron-builder не поддерживает
такую кросс-сборку. Скрипт проверяет платформу и собирает архитектуры отдельно:

```bash
npm run dist:mac:arm64  # Apple Silicon
npm run dist:mac:x64    # Intel
npm run dist:mac        # обе архитектуры последовательно
```

Результат в `dist/`:

- `Spider-Solver-1.0.0-mac-arm64.dmg` и `.zip`;
- `Spider-Solver-1.0.0-mac-x64.dmg` и `.zip`.

Установщики не подписаны и не нотаризованы. На Windows при первом запуске
может появиться SmartScreen; на macOS потребуется «Открыть» через контекстное
меню или `xattr -dr com.apple.quarantine "Spider Solver.app"`.

> В `dist/` могут остаться файлы `0.1.0` — это старые артефакты до обновления
> версии. Для получения пакетов `1.0.0` пересоберите установщики; при желании
> удалите старые файлы перед сборкой.

### GitHub Actions

В репозитории есть workflow `.github/workflows/build-macos.yml`. Он запускается
вручную (`workflow_dispatch`) на macOS-раннере, выполняет `npm ci`, `npm test`
и собирает DMG/ZIP для `arm64` и `x64` отдельными job-ами. Артефакты:

`Spider-Solver-macos-{arm64,x64}-dmg` и `Spider-Solver-macos-{arm64,x64}-zip`.

Windows-сборка в CI не настроена — её можно сделать локально командами выше.

## Как это устроено

| Файл | Роль |
| --- | --- |
| `src/model.js` | Чистая модель пасьянса: колода из 104 символов, раздача, перекладывание хвостов, сборка K→A, проверка победы. |
| `src/solver.js` | Beam search с эвристикой на одномастные убывающие серии и portfolio restarts. |
| `src/solver-worker.js`, `src/solver-client.js` | Поиск в отдельном потоке; прогресс и остановка через `SharedArrayBuffer`. |
| `src/page-helpers.js` | Общие функции внедрения в страницу: чтение состояния и ходы через `game.playHistoryItem`. |
| `src/browser.js` | Playwright-драйвер для CLI и веба, постоянный профиль браузера. |
| `src/electron-browser.js` | Драйвер для встроенного `WebContentsView` — отдельного окна не создаёт. |
| `src/runner.js`, `src/server.js` | Оркестрация запусков, статусы и логи, HTTP/SSE API. |
| `src/modes.js` | Правила числа попыток для обычной, ежедневной и фиксированной колоды. |
| `src/report.js` | Текстовый отчёт с нумерованными ходами и кодом колоды. |
| `src/cli.js` | Аргументы командной строки, перебор колод, проверка победы. |
| `public/` | Интерфейс: управление, прогресс, журнал и встроенная игра. |
| `electron/` | Главное окно Electron, IPC, профиль, папка логов и меню. |
| `scripts/build-mac.mjs` | Проверка платформы и сборка macOS под arm64/x64. |

Код колоды сайта кодируется 104 символами (`index = (suit - 1) << 4 | nominal`,
масти 3 и 4). Ходы отправляются как `{type:'movecards', from, to, count}` и
`{type:'deckclick'}` через `game.playHistoryItem` — тот же путь, который сайт
использует при воспроизведении истории.

## Тесты

```bash
npm test
```

Набор из 41 теста проверяет модель и легальность ходов, настоящие победы
решателя (включая worker и перезапуски), остановку поиска и повторный запуск,
статусы `Runner`, API сервера, запись отчёта, ежедневный режим, историю сайта,
раскладку встроенной игры, окно Electron, UI логирования и macOS-скрипты сборки.

## Ограничения и устранение проблем

- Решатель эвристический: на части колод решение не находится. Помогают
  `--attempts`, `--max-nodes`, `--timeout` и перебор колод через `--games`.
- Сайт может изменить вёрстку или внутренний API — тогда нужно обновить
  `src/page-helpers.js` и драйверы браузера.
- Если страница игры не загружается за SSL-прокси, попробуйте
  `SPIDER_IGNORE_CERT_ERRORS=1` (только для отладки).
- Неподписанные сборки требуют подтверждения при первом запуске (Gatekeeper /
  SmartScreen).
- «Стоп» во время выполнения ходов срабатывает между ходами: текущий ход
  доводится до конца, чтобы не оставить игру в неконсистентном состоянии.
